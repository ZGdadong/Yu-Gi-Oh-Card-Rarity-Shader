## 1. 一句话讲清楚原理

**罕贵度的差别几乎全在"哪一块被加工了"上。**

面闪只有卡图有闪膜、银字只有卡名的笔画烫银、收藏闪是边框+卡名+卡图外框有彩虹。
所以先**从图里量出几块区域**，再让每个着色器选一块来加工（**星数/阶数带**与
**属性圆**也在其中 —— 它们落在卡框上，卡图遮罩够不到；逐条核对见
[`rarity-shaders.md` §3](rarity-shaders.md)）：

| 区域 | 怎么定出来的 | 占比 |
| --- | --- | --- |
| **卡名笔画** | 卡名带里**按暗度抠**（不猜字形位置，换字体也跟得住），再膨胀 2px | 1.85% |
| **卡图** | 插画本身（亮度剖面量到的：x 96–718、y 224–836） | 40.7% |
| **效果框** | 含 ATK/DEF 带（y 878–1135） | 18.9% |
| **卡框** | 整卡 − 卡图窗外框 − 效果框（着色器按矩形现算） | 37.2% |
| （卡图外环） | 卡图窗外框 − 卡图内容 | 3.2% |
| **星数 / 阶数带** | 名带与卡图窗之间那一条，**整宽**（等级星靠右、超量阶数星靠左，一条带子两种都盖得住） | 遮罩码 11 |
| **属性圆** | 名字后面那个圆（光/暗/地/水/炎/风/神），**走圆掩膜**不当方块框 —— 圆心 (0.8831, 0.0759)、半径 0.0320 卡高 | 遮罩码 12 |

渲染就是：**背景 → 投影 → 原始卡面 → 一层层叠工艺**，每层采样同一张"没加工过的原始印刷"，
自己决定输出什么颜色、留多少 alpha。

## 3. 17 个工艺

| 类别 | 工艺 | 机制一句话 |
| --- | --- | --- |
| **闪膜** | `holo` | 宽光带全息，相位场由"视角 + 卡面亮度 + 噪声"驱动 |
| | `parallel` | 整卡极细的**不规则拉丝**膜，**颜色只沿垂直线方向缓慢变** —— 这是爆闪的观感关键（原来是等距线栅，6.6px 一根，看着像 CRT 扫描线，已换掉，见 §3 末） |
| | `diagonal` | 斜光栅 + 沿栅格随机的碎片色相，碎片边发白 |
| | `prismatic` | 正反两个方向的光栅交叉，**交叉点炸白** = 白碎 |
| | `starfoil` | 一格一颗四角星（astroid 曲线） |
| | `mosaic` | 方格，格线压暗 |
| | `voronoi` | Voronoi 碎片，碎片边发亮 |
| **图案** | `kc` | **电路板**膜：走线成组地朝一个方向走、45° 折角、隔一段一个过孔，少数是粗"电源线"，板上留着一片片没铜的空地（**不是迷宫式的网格**，四层铜互相交叉）；**鼠标指到哪儿，那一块附近就显形**，配色**按到光标的距离**在蓝→绿→黄→橙→红之间**连续渐变**（软斑半径 0.31 卡高，窗口 ≈ 卡面 45%，对焦最亮、往外渐变） |
| | `millennium` | 4 个象形字按格随机拼（**风格化近似**）：字面随视角变色，**没有竖线**；一个角度最多 45% 的字显形，另加全图小金点。格子按像素等比（旧的 `squareGrid` 除以长宽比会把图案压扁） |
| | `stamp` | 20th / 25th 水印，斜排密铺 |
| **工艺** | `emboss` | **把卡面明暗当高度场**求梯度得法线，再用方向光打亮 |
| | `ghost` | 去色 + 提对比 + 冷偏移 → 银白幽灵（只压遮罩选中的那一块）；观察角到了波峰那一段，整片换成面闪的膜 |
| | `metal` | 明暗**映射**到金属色 + 拉丝高光（不是加增益，否则整卡炸白糊掉） |
| | `rainbow` | 以高光点为圆心按极坐标取色相，鼠标一动整圈转 |
| | `name` | 卡名笔画烫金 / 烫银 / 换色 |
| **加光** | `glitter` / `gloss` | 细碎亮点 / 卡面扫光（这两个走**加法混合**，只输出"多加了多少光"） |

外加 4 个基础件（`base` `shadow` `bg` `maskdebug`）= **21 个片段着色器**，
以及一个 **3D 倾斜顶点着色器** —— 鼠标在卡上移动时卡片真的绕 X/Y 轴转，
同样这两个角度驱动闪膜的衍射相位（拿实卡看闪膜本来就是捏着卡慢慢转）。
**默认鼠标指到哪、那一侧往里沉**（像手指按住卡片），面板里可反向。

> **图案膜的"可见窗口"**：`kc` 与 `millennium` 这两层都铺满整卡，但**永远只显形一部分**
> —— 实卡的图案膜本来就分成许多组，只在一个条件满足时才把光反进眼睛。两种驱动：
> **KC 闪跟着鼠标**（以光标为圆心的软斑，半径 0.31 卡高 → 窗口 ≈ 卡面 45%，对焦那一圈
> 最亮、往外一路渐变到边缘），**千年闪跟着观察角**（一条随视角滑动的斜波带，
> 任何角度最多 45% 上下、代码里夹死 45%）。机制与实测见
> [`rarity-shaders.md` §4](rarity-shaders.md)。
>
> **爆闪的线栅也去掉了**：`parallel` 原来是一条铺满整卡的**等距正弦线栅**（线密度 92，
> 也就是卡高上 92 个周期），亮度摆幅 2.8 倍。卡片只有 400 多像素高，算下来 **6.6px 一根**
> —— 眼睛看得清清楚楚，NPR / RPR / SPR / UPR / PR 这五条看着都像 **CRT 扫描线**。
> 实卡的膜线距比像素细得多，眼睛只看到"一片会一起扫过去的光"。现在换成**不规则的拉丝**
> （各向异性噪声，有方向感、没有周期）。判据是**谱**：卡片区行均值做 DFT，线栅那一根从
> **141.7 倍**掉到 **21.7 倍**（"完全不画织构"的地板是 15.7 倍），而膜的浓淡几乎没动
> （卡面均值 168.8→170.9、色相跨度 0.913→0.907、相对平卡 N 的可见度 29.6→27.0）。
> 详见 [`rarity-shaders.md` §4](rarity-shaders.md)。

## 4. 换卡图 & 多语言

这两块都是"加东西不用改代码"的设计，细节见 [`rarity-shaders.md`](rarity-shaders.md) §10 / §11。

### 换卡图：`images/` 下有几张就认几张

```powershell
# 把图片丢进 images/，然后
node tools/embed-card.mjs      # 重新烘焙所有卡图与掩膜
```

刷新页面，参数面板最上面那个「卡图」下拉框里就有了。**卡片外沿是自动识别的**
（`tools/lib/detect.mjs`，烘焙与验证共用同一份实现）。

识别的三步都是实测换出来的：阈值写死 0.85 → 换一张"卡片只占画面 47% 宽"的图就失效；
改成自适应阈值 → 浅色卡贴浅色背景时上沿对比度不够、比例算错；
最后加"用已知的 59:86 比例校正"才稳。四个合成用例的四边误差是 `[0,0,1,1]` / `[0,11,1,0]` / `[0,0,1,1]`。

**换卡要注意**：卡框/卡图窗/效果框那几个矩形按**游戏王标准版式**写死、所有卡共用
（灵摆卡、连接怪、无效果怪对不上，得在 `tools/embed-card.mjs` 的 `CARDS` 表里按文件名覆盖）；
卡名笔画靠 **Otsu + 少数派自动判极性** 从图里抠（深字浅底 / 白字黑底都认，实测 7 张里 `Raidraptor` 就是白字黑底；判错可以在 `NAME_INK` 里钉死）。

### 多语言：`Languages/` 下一个语言一个文件

```js
global.CardI18nPack['zh-CN'] = { code: 'zh-CN', name: '中文', texts: { 键: 文案 } };
```

| 语言 | 键数 |
| --- | --- |
| `zh-CN` 中文 | 347 |
| `en-US` English | 347 |
| `ja-JP` 日本語 | 347 |

347 键 = 界面骨架 33 + 分节/分组 9 + 43 条罕贵度 × 4 项 + 3 条 code + 61 个参数（label 61 个 + 有 hint 的 41 个）+ 25 个预设 + 每张卡 3 项。
加一种语言 = 复制一个包改名 + 在 `languages.js` 里加一行，右上角下拉框即时切换。

**语言包是 `.js` 不是 `.json`**：`fetch('./Languages/xx.json')` 在 `file://` 下会被 CORS 拦掉，
而"双击 index.html 就能跑"是这个项目的硬要求。机制（localStorage 记住选择、缺键回退、
`{var}` 插值）与参考的那份文档一致，只有加载方式不同。

三层兜底：**当前语言包 → zh-CN 包 → 代码里的中文原文**。`js/ui.js` 里所有文案都用
`I18N.tOr(键, 原文)`，所以一个语言包都没加载成功也不会满屏裸键。

## 5. 哪些做不出来（没有藏起来）

| 文档里的说法 | 为什么做不出来 | 怎么处理 |
| --- | --- | --- |
| **NR 平罕**："外观与平卡相同，但封入率异常低" | 这条罕贵度的**唯一特征是封入率**，没有画面差别 | 渲染成和 N 完全相同，**一个像素都不改** |
| **UTR**："触摸有凹凸" | 触摸是物理属性 | 只做视觉浮雕，文字里明说触摸做不出来 |
| **CP / TP 等**："不同赛事、地区版本差异大" | 文档自己就说没有统一工艺 | 只给示意配方，明确标注 |
| **韩文版 / 亚英** | 不是新工艺，是发行版本 | 借配方当代表，说明里写清 |
| **卡面右下角的编号字母** | 图上没有，而且改它属于伪造卡面 | 只在页面说明条上显示代码 |
| **价格** | 受发行量/强度/品相/语言影响 | 完全不做 |
| **"第 10 期以后 SR / UR / SER 的星星与属性也有闪膜"** | 这条**原始文档里没有**，是另一份资料说的；日文维基对 Super Rare 的定义至今只写"イラストがホイル加工" | 按那份资料做了（SR/UR/SER/UTR 各补一层薄薄的星带+属性圆），但**在文档里标了出处与问号**，删掉 `js/rarities.js` 里那 4 行 `starAttr(...)` 就回到"只闪卡图" |

另外几条是**取值上的取舍**：`Starlight`/`PSER`/`QCScR` 文档都只写"整张卡覆盖闪膜"、
没写形状，我按观感做成三种不同的膜好让它们**看得出区别**；千年闪的"埃及文字"是
**风格化近似**不是考据；闪膜的流动动画是我加的（实卡不动，但屏幕上需要一点流动感）。

## 6. 验证

```powershell
node tools/verify.mjs      # 63 项：归档 / 掩膜 / 罕贵度表 / 编译 / 确定性 / 布局 / 倾斜 /
                           #        检测器合成用例 / 多卡图 / 多语言 / hash
node tools/effects.mjs     # 43 个罕贵度 + 17 个工艺 + 61 个参数 + 25 个预设实测
node tools/doc-check.mjs   # 核对两份文档里可机器判定的说法（56 项）
```

- `verify.mjs`：**63/63 PASS**。
- `effects.mjs`：43 个罕贵度 / 17 个工艺 / 25 个预设全过；**61 根参数滑条全部接通**。
  改之前这里长期是 39/53（14 个没接通），根子在**扫描工况**而不在渲染：
  逐参数扫描把所有工艺叠在一张卡上，后面那些铺满整卡的层把前面盖住了，于是"改区域"
  看不出变化（实测同一根滑条在面闪 SR 上是均值差 **10.6** / 单通道最大 **117**，
  在合成卡上只剩 **0.001 / 1**）；`card` 那次则是扫描脚本对 `card` 型参数**没有候选值**
  （`min`/`max` 都没定义，算出来是 NaN，最后全落回第 0 张卡）。
  现在给「区域」组每一根滑条配一个"**只留一层、并且这一层正好加工那块区域**"的工况
  （星带 → 遮罩码 11、属性圆 → 12、卡图外框 → 7、插画 → 1、效果框 → 4），
  `card` 型参数直接给几个真的不同的卡号 —— 于是 20 根区域滑条全部实测生效。
- `doc-check.mjs`：**48/56** —— 8 项没过，全部是**文档落后于代码**、与渲染无关：
  §3 那张区域表写的是"卡片相对比例"、`js/card-textures.js` 里存的是"整图相对"，
  两套口径对不上（5 项）；纹理尺寸那行还停在"裁 + 补 4% 留白"的旧做法
  （749×1113，现在是整张原图 813×1185）；掩膜覆盖率那行是按旧数字钉死的
  （卡名 2.30% → 1.85%、卡图 44.2% → 40.7%）。要收干净得把 §3 按新口径重写一遍。

**逐参数扫描**会把每个参数改一遍、看画面动没动；**逐工艺扫描**会把
每个工艺单独留在卡上、和"平卡 N"逐像素比 —— 这两条是抓 bug 的主力。

### 工具真的抓出来的东西

前 8 条是扫描类工具抓的，后面几条是"动手造第二张卡 / 把像素摊开看 / 写探针"抓的：

1. **部分覆盖的层会把整张卡重画一遍** —— `name` 写成 `if (mask<0.004) return tex` 看着无害，
   其实返回的 `tex` 带 alpha=1，等于在上一层成果上把原始印刷贴回来。
   表现是"黄金闪怎么调都不变金"，而且**完全不报错**。
2. **打开参数面板卡片会变小** —— 画布只监听了 window 的 resize，stage 变窄时没重新分配
   绘制缓冲区，被 CSS 缩着显示。现在用 `ResizeObserver` 盯 stage。
3. **倾斜方向两个轴是相反的** —— 鼠标往右是"右边朝你翘"，鼠标往下却是"下边往里沉"。
   单看一个方向都说得通，斜着晃鼠标就发现两边在打架。现在统一由一个参数控制。
4. **"关掉鼠标驱动倾斜"后定格画面照样跟鼠标跑** —— 实时与定格各抄了一份倾斜计算，
   定格那份漏了开关（单通道差 252）。现在共用一个 `targetTilt()`。
5. **hash 里的 `'0'` 被读成"开"** —— `clampParam` 对开关写 `v ? 1 : 0`，
   而 hash 解出来是字符串，`'0'` 在 JS 里是**真值**。
6. **canvas 的预乘 alpha 会吃掉掩膜** —— 掩膜放进 alpha 通道后，那两块的其它通道被除以 0 抹平；
   而且画面看着完全正常（GPU 上传不经过 canvas），只有把掩膜过一遍 canvas 才看得见。
7. **卡面扫光有 40% 时间是死的** —— 实测 t=2~5s 整整四秒卡片区平均差正好是 0。
8. **"覆盖卡名颜色"打开等于没打开** —— 默认色和"银字"的银色几乎一样。
9. **圆角半径是拍脑袋写的** —— `CORNER_R = 0.042` 注释里写着"从图上量出来的"，其实没量过。
   把像素摊开一看，这张卡的角是**方**的（`y=26` 那行 `x=26` 就已经是卡片了），
   0.042 × 689 ≈ 29px 等于把卡片自己的四个角各削掉 29px。
10. **卡片外沿检测的阈值写死 0.85** —— 只对"卡片铺满整幅图"有效。造一张"卡片占画面 47% 宽"
    的测试图立刻失效，退化成整张图，**卡名掩膜跟着变成 0%**。
11. **投影被调成了黑边** —— 为了让 `shadowOn` 能被参数扫描判成"接通"，我把投影加到了
    0.70 不透明 / 1.7% 偏移；量出来卡片下沿外侧亮度只有 **9**（远处背景 29），就是一条黑边。
    现在改成"贴着卡片的浅投影"（0.42 / 0.8% / 更宽的模糊）。
12. **检测器的测试里，标准答案自己写错了** —— 素材是"卡片 + 四周 4% 留白"的纹理，
    真值却按"整张图 / 粘贴位置"算，于是每条都差 4%（几十像素），
    看着像检测不准，其实是标准答案错了。
13. **`like:` 只认 `null`、不认"没写这个键"** —— DT 那 6 条（DT-N ~ DT-PR）压根没写
    `layers` 这个键（undefined），而判空写的是 `r.layers === null`，于是解析 `like` 的分支
    一次都没进，后面的兜底把它们统统变成"一个图层都没有"：**DT-R / DT-SR / DT-UR /
    DT-SER / DT-PR 渲染出来和平卡 N 一模一样**（探针实测逐像素差 0.000），
    文档里那句"用 `like:` 指过去、图层只有一份定义"一直是空话。
    判空改成 `== null` 之后，五条与 OCG 同名罕贵度逐像素相同（差 0.000），
    而**故意什么都不加**的 `N` / `NR` / `DT-N` 不受影响（它们写的是 `layers: []`，
    `[]` 不是 null / undefined）。见 `tools/.cache/probe-dt-like.mjs`。
