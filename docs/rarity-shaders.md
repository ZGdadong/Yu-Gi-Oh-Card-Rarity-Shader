## 1. 一页速查

**17 个工艺着色器 + 4 个基础件 = 21 个片段着色器**，外加 1 个 3D 倾斜顶点着色器。

| 类别 | 着色器 | 干什么 |
| --- | --- | --- |
| **基础件** | `base` `shadow` `bg` `maskdebug` | 直通卡面 / 投影剪影 / 背景 / 掩膜调试图层 |
| **闪膜家族** | `holo` | 宽光带全息（面闪的底子） |
| | `parallel` | 整卡极细的**不规则拉丝**膜 + 沿垂直方向的缓变色带（爆闪；**不是等距线栅**，见 §4） |
| | `diagonal` | 斜向碎冰（银碎） |
| | `prismatic` | 正反交叉光栅、交叉点炸白（白碎） |
| | `starfoil` | 一格一颗四角星 |
| | `mosaic` | 方格闪膜 |
| | `voronoi` | Voronoi 碎片闪膜 |
| **图案类** | `kc` | **电路板**膜（**四层铜**：每层走向/留白/疏密/线宽都不同，互相交叉；45° 折角 + 过孔 + 留白空地）；配色是**蓝→绿→黄→橙→红**的**连续渐变**，按到光标的距离铺开；**鼠标附近那一块**显形（窗口 ≈ 卡面 45%，对焦最亮、往外渐变） |
| | `millennium` | 埃及象形字图案膜（**没有竖线**），任何角度最多 45% 显形 + 全图小金点 |
| | `stamp` | 周年水印（20th / 25th） |
| **工艺家族** | `emboss` | 浮雕（把明暗当高度场打光） |
| | `ghost` | 银白幽灵（鬼闪）：只压怪物图框，某些角度会滑成面闪 |
| | `metal` | 金 / 铂金箔 + 拉丝高光 |
| | `rainbow` | 跟着视角转的彩虹反射（收藏闪） |
| | `name` | 卡名工艺（银字 / 金名 / 红碎 / 白碎） |
| **加光类** | `glitter` | 细碎闪光点（加法混合） |
| | `gloss` | 卡面扫光（加法混合） |

三个数字值得记住：

- **17 个工艺里有 2 个是加法混合**（`glitter` / `gloss`），只输出"多加了多少光"，不输出卡面颜色。
- **4 个基础件里只有 2 个会采样卡面纹理之外的量**：`bg` 完全不采样卡面，`maskdebug` 只采样掩膜。
- **43 条罕贵度里只有 3 条是"什么都不改"**：`N`、`NR`（平罕）、`DT-N` —— 前两个与平卡的差别不在画面上。

## 2. 渲染架构：draw step

一张卡是这样叠出来的（每一步都是一次 `glDrawArrays` 画同一个卡片四边形）：

```
① bg          全屏        一道渐变 + 缓慢横移的光带
② shadow      卡片四边形   卡片的黑色剪影（25 抽样软边）
③ base        卡片四边形   原始印刷（或者掩膜调试图）
④..⑥ 工艺层   卡片四边形   按 js/rarities.js 里那份配方，一层一层叠上去
```

关键约定：**所有层采样的都是同一张 `uTex`（那张没加工过的原始印刷）**。
所以叠几层就是几层，互不污染，顺序只影响混合先后。

顶点阶段做了一件 Balatro 那个项目没做的事：**真正的 3D 倾斜**。
拿实卡看闪膜本来就是"捏着卡慢慢转"，所以鼠标在卡上移动时卡片真的绕 X/Y 轴转动，
而这两个角度**同时**被送去驱动闪膜的衍射相位（`uView`）—— 观感才对得上。
为了让花纹跟着卡片一起被透视，`gl_Position` 的 w 用的是相机空间深度（不是 1），
这样纹理坐标按透视插值，倾斜时卡面不会错位。

## 3. 卡片被切成哪几块

罕贵度的差别**几乎全在"哪一块被加工了"**上：

- **面闪 SR**：只有卡图窗有闪膜，卡名不闪
- **银字 R** ：只有卡名的**笔画**是银色烫金
- **收藏闪 CR**：边框、卡名、卡图外框都有彩虹
- **20th SER**：卡名是红的，效果框上还有 "20th" 水印

所以着色器必须先知道"卡名在哪、卡图窗在哪、效果框在哪"。这些矩形**是从这张图上量出来的**
（`tools/probe-card.mjs` 打亮度剖面找硬边），不是抄的规格表：

| 区域 | x0 | y0 | x1 | y1 | 怎么来的 |
| --- | --- | --- | --- | --- | --- |
| 卡名带 `nameBand` | 0.030 | 0.020 | 0.848 | 0.088 | 框住字，实际笔画靠暗度抠（x1 卡在光属性图标之前） |
| 卡图窗外框 `artOuter` | 0.0736 | 0.1520 | 0.9277 | 0.7280 | 插画四周那圈深色框的外沿 |
| 卡图内容 `artInner` | 0.0920 | 0.1751 | 0.9093 | 0.7162 | 插画本身 |
| 效果框 `textBox` | 0.0380 | 0.7533 | 0.9620 | 0.9806 | 含 ATK/DEF 带 |
| 等级星带 `starBand` | 0.0400 | 0.1000 | 0.9600 | 0.1520 | 星位那一行 |

（数字是**卡片相对比例**，v=0 是卡片上沿。量出来的像素值在 `tools/embed-card.mjs` 顶部。
⚠️ 最后一行那个 `starBand` 是烘焙时留下的常量，**渲染并没有用它** —— 运行时真正在用的
"星数 / 阶数带"见下一节。）

### 后来加的两块：星数 / 阶数带、属性圆

除了上面这五块，侧栏「区域」里还有两块**后加的**（遮罩码 **11 / 12**）——
它们说的还是同一张卡上的两处地方，但**只活在运行时**，不进烘焙：

| 区域 | 形状 | 默认值（cardUV，x × 813 / y × 1185 就是像素） | 怎么定出来的 |
| --- | --- | --- | --- |
| 星数 / 阶数带 `uRectStar` | 矩形，**整宽的一条带** | x 0.0320 ~ 0.9350 · y 0.1200 ~ 0.1800（≈26~760px · 142~213px） | 星盘位置是从图上量的：A-to-Z 的 10 颗星 y 153~205px、Blue-Eyes 的 8 颗 150~192px、超量那张的 13 颗阶数星 146~192px。带子取并集再留几像素余量 |
| 属性圆 `uCircleAttr` | **圆**（圆心 + 半径） | 圆心 (0.8831, 0.0759) · 半径 0.0320（≈(718, 90)px · 38px） | 名字后面那个属性图标。三张卡实测圆心 (716.5, 88.8) / (718, 89) / (718.8, 92.3)，半径含外面那圈金边 |

两处设计上的取舍，都是看图定下来的：

- **星带是整宽的，不是"把每一颗星框起来"**：星位随召唤方式换边 —— 等级星靠右
  （10 颗到 688px 为止）、**阶数星（超量）从最左边 x=33px 就开始**，一条整宽的带子两种都盖得住。
  左右沿收窄一点就会切掉排头 / 排尾那几颗星（`tools/.cache/probe-newregions-outline.mjs`
  把轮廓画在卡图上，一眼就能看见）。
- **属性图标走圆掩膜，不走矩形**：它是一个圆（外面一圈金边 + 里面的属性字），
  用矩形去框会连带把卡框那圈深色边一起加工，看着就是个方块。
  `circleMask` 把 x 先乘长宽比再算距离（和 `isoUV` 同一套），所以圆不会被拉成椭圆；
  **半径的单位是"卡高 = 1"**，和「卡片圆角」同一个口径。

> **为什么这两块不进烘焙**：它们都是**版式常量**，没有"按卡检测"这回事
> —— 星带的烘焙常量（`starBand`）映射过来在 7 张卡之间只差第 4 位小数，
> 而且上下都偏（烘焙带 139~198px，实测星盘 146~205px，会切掉星盘下沿 7px）；
> 属性圆在 `js/bake.js` 的 REGIONS 里压根没有。
> 所以这两块**不吃「手动区域」那个开关**：两种模式下都用手调值，拖滑条立刻生效。
>
> 顺带说明：星带与属性圆**落在卡框里**（"整卡 − 卡图窗 − 效果框"那一块），
> 所以 11 / 12 交出来的是**那一块本身、不含卡框** —— 想让它们压在卡框工艺上面，
> 配方里把它们排在后面就行（和别的层一样按顺序叠）。

### 哪些罕贵度会加工这两块（含一次逐条核对）

"高罕贵度会把星位与属性图标一起加工"这个说法**原始文档里没有**（那份文档只写
"卡图全息""卡图有浮雕立体质感"这类"卡图"级别的描述），它来自另一份资料。
把它逐条对着 `js/rarities.js` 核了一遍，结论是：**资料里能站住的那几条，本项目本来就已经
做到了** —— 因为星位与属性图标落在**卡框**里，而金箔 / 铂金 / 彩虹 / 爆闪用的正是
"金属区（卡框 + 卡名 + 卡图外环）"或"整卡面"遮罩：

| 资料里说的 | 本项目原来的配方 | 星位 / 属性圆有没有被加工 |
| --- | --- | --- |
| Parallel Rare：卡面整体加工 | `parallel[整卡面]` | ✅ 本来就有 |
| Gold Rare (GUR)：金色箔 | `metal[金属区]` ×2 | ✅ 本来就有（金属区含卡框） |
| Gold Secret Rare (GScR) | `metal[金属区]` ×2 + `diagonal` | ✅ 本来就有 |
| Platinum Rare (PlR / PlScR) | `metal[金属区]` ×2 | ✅ 本来就有 |
| Collector's Rare (CR)：彩虹反射 | `rainbow[金属区]` + `rainbow[卡图]` | ✅ 本来就有 |
| Super Rare：闪膜 | `holo[卡图]`（卡图遮罩够不到卡框） | ❌ → **这次补上** `holo[13]` |
| Ultra Rare：闪膜 | `holo[卡图]` + 金名 | ❌ → **这次补上** `holo[13]` |
| Secret Rare：碎箔 | `diagonal[卡图+卡名]` | ❌ → **这次补上** `diagonal[13]` |
| Ultimate Rare：浮雕 | `emboss[卡图]` + `emboss[卡名]` + `emboss[效果框的字]` | ❌ → **这次补上** `emboss[13]` |

补的方式是**在原有配方后面再加一层**，遮罩用新加的 **13 号（星带 + 属性圆）**，
强度取该工艺的一半上下（面闪 / 金闪 0.50、银碎 0.50、浮雕 0.62）—— 这样
"面闪只闪卡图"那条分界线还在（卡图那层强度是 0.95 / 1.0，星位那层只是薄薄一层），
只是星位与属性不再是"原印刷"。`starAttr()` 这个配方块就是干这件事的。

> ⚠️ **这一条要打个问号**：那份资料说"第 10 期以后 SR / UR / SER 的星星与属性也有闪膜"，
> 而日文维基对 Super Rare 的定义至今只写"**カードのイラストがホイル加工**"（只提插画）。
> 本项目**不假装考证**：补上它是按你给的资料做的，强度也取得很轻。
> 想严格按原始文档（这几条只闪卡图）→ 把 `js/rarities.js` 里那 4 行 `starAttr(...)`
> 删掉就回去了；想让它更显眼 → 调大那一层的强度。

### 掩膜的通道分配

`tools/embed-card.mjs` 在烘焙时把这些区域算成一张和卡图同尺寸的 RGBA 掩膜：

| 通道 | 内容 | 怎么算出来的 |
| --- | --- | --- |
| **R** | 卡名笔画 | 只给**卡名笔画**烫银。笔画掩膜是按暗度从图里抠出来的（R 通道），所以银色是沿着字形走的，不是盖一个矩形。 |
| **G** | 卡图内容 | `artInner` 矩形 → 羽化 1.5px |
| **B** | 效果框 | `textBox` 矩形 → 羽化 1.5px |
| **A** | 卡片剪影 | 卡内处处为 1（圆角与边缘羽化） |

**"卡框"和"卡图外环"不进掩膜**，由着色器按 `uRectArtOuter` 现算：

```glsl
float frame = m.a * (1.0 - outer) * (1.0 - m.b);   // 整卡 − 卡图窗外框 − 效果框
float ring  = outer * (1.0 - m.g);                 // 卡图窗外框 − 卡图内容
```

> ### ⚠️ 为什么"卡框"不能放 alpha 通道
>
> 第一版把 A 通道定义成"卡框"，结果**卡图窗与效果框那两块的掩膜整个消失了**：
> 那两块上卡框掩膜 = 0 → alpha = 0，而 canvas 的像素是**预乘 alpha** 存的，
> `toDataURL` / `getImageData` 会反预乘 —— 除以 0，G/B 通道被抹平。
>
> 更阴的是**画面看着完全正常**：GPU 上传走的是 `<img>` 里的原始像素，不经过 canvas，
> 所以只有"把掩膜过一遍 canvas"的代码才会看到问题。`tools/verify.mjs` 里那条
> "卡图 / 效果框掩膜能挺过一次 canvas 往返"就是专门盯这个的。
>
> 现在的做法把 alpha 让给"是不是卡上的像素"（卡内恒为 1，怎么反预乘都不丢），
> 卡框交给矩形现算。

### 卡名笔画是怎么抠出来的

不猜字形位置，直接**按暗度抠**：卡名带里的字比底板暗得多（实测笔画区平均亮度 **0.49**，
底板 **0.89**），按阈值取一遍再膨胀两像素，就把笔画掩膜拿到了 —— 换任何字体、任何字距都跟得住。

膨胀两像素还有个副作用正好对：实卡上烫金本来就比印刷笔画粗一点点。

### 留白与内容矩形

卡图裁到卡片外沿、四周补 4% 透明留白（给投影和倾斜留位置），再削圆角。
纹理是 **749×1113**，卡片内容是 **689×1024**。

留白是**整数像素**，换算成比例之后横竖不可能同时正好 4%（竖边 45px = 4.043%，
横边 30px = 4.005%），所以 `js/card-textures.js` 直接存一个 `contentUV` 矩形，
着色器按矩形换算卡片坐标：

```glsl
vec2 cardUV(vec2 uv) { return (uv - uContent.xy) / (uContent.zw - uContent.xy); }
```

差那 0.4% 会让"卡图窗外框"这类矩形掩膜整体错开半个像素 —— 不至于难看，但没必要。

## 4. uniform 协议

每次 draw step 会发这些：

| uniform | 类型 | 说明 |
| --- | --- | --- |
| `uTex` | sampler2D | 卡面（**永远是原始印刷**） |
| `uMask` | sampler2D | 工艺区域掩膜（R 卡名 / G 卡图 / B 效果框 / A 卡片剪影） |
| `uStamp` | sampler2D | 图案图集 4×2 格：KC / 20th / 25th / 菱形 / 安卡 / 荷鲁斯之眼 / 王名圈 / 水波鸟 |
| `uContent` | vec4 | 卡片内容在纹理里的归一化矩形 |
| `uRectArtOuter` | vec4 | 卡图窗外框的矩形（卡片相对坐标） |
| `uRectArtInner` | vec4 | 卡图窗内沿（插画本身）的矩形 |
| `uRectTextBox` | vec4 | 效果框（含 ATK/DEF 带）的矩形 |
| `uRectStar` | vec4 | **星数 / 阶数带**的矩形（整宽的一条） |
| `uCircleAttr` | vec4 | **属性圆**：(圆心 x, 圆心 y, 半径, 软边)，半径单位是"卡高 = 1" |
| `uResolution` | vec2 | 目标像素尺寸（浮雕求梯度、投影模糊要用） |
| `uTime` | float | 运行时钟（秒） |
| `uView` | vec2 | 视角方向 −1..1，来自卡片倾斜角 |
| `uViewPt` | vec2 | 高光点在卡片坐标里的位置（彩虹反射以它为中心） |
| `uAspect` | float | 卡片宽/高（0.6729），程序化花纹靠它做各向同性 |
| `uSeed` | float | 每张卡的固定噪声相位（一览模式里每格不同） |
| `uP0` `uP1` `uP2` | vec4 | **该效果自己的参数**，含义见 §5 |
| `uCol` | vec4 | 该效果自己的工艺色（金 / 银 / 铂金 / 红 / 白…） |

### 遮罩选择码

`pickMask(m, sel, uv)` 把"加工哪一块"做成一个数字 —— 这份清单就是本文档的核心词汇表：

| 码 | 含义 | 码 | 含义 |
| --- | --- | --- | --- |
| 0 | 全卡面 | 6 | 金属区（卡框 + 卡名 + 卡图外环） |
| 1 | 卡图 | 7 | 卡框 + 卡图外环 |
| 2 | 卡框 | 8 | 效果框里的字（按暗度从效果框里抠） |
| 3 | 卡名 | 9 | 卡框 + 卡名 |
| 4 | 效果框 | 10 | 卡图 + 卡名 |
| 5 | 卡图 + 卡框 | 11 | **星数 / 阶数带**（名带与卡图窗之间那一条，整宽） |
| | | 12 | **属性圆**（名字后面那个圆，见 §3） |
| | | 13 | **星带 + 属性圆**（两块一起 —— 面闪 / 金闪 / 银碎 / 浮雕补的那一层用它） |

11 / 12 是后加的两块，**13 是它们的并集**（"星位与属性一起加工"用这一档，省得写两层）。
金箔 / 铂金 / 彩虹 / 爆闪那几条**不需要**它们：那些工艺用的是"金属区"或"整卡面"遮罩，
本来就把这两处一起加工了 —— 逐条核对见 §3 那张表。

**想单独看这两块**：面板「调试」组有一根「区域演示」滑条（0 关 / 1 只加工星带 /

### 强度是怎么算的

每条配方的**第 0 号参数（`p0.x`）统一是强度**，实际发出去时乘三样东西：

```
实际强度 = 配方里的强度 × 工艺总强度(intensity) × 该工艺的倍率(mHolo / mMetal / …)
```

面板上没有把每个着色器的每个 uniform 都做成滑条（那会是几百个），
而是每个工艺一个**倍率**——目的是让人一边拖一边看清"这个工艺到底在干什么"。

### 图案膜的"可见窗口"：永远只看得到一部分

图案膜（KC 闪的电路、千年闪的象形字）都**铺满整卡**，但**永远只显形一部分** ——
实卡的图案膜本来就是"整片膜分成许多组，每组只在某个条件满足时才把光反进眼睛"。
这一部分由**可见窗口**决定，`js/shaders.js` 里有两套，各管一个工艺：

| 窗口 | 用在哪 | 可见面积 | 长什么样 |
| --- | --- | --- | --- |
| `cursorGate(spy, radius)` | **KC 闪** | 半径 0.33 卡高 → 实测 ≈ **45%** 卡面 | **鼠标指到哪儿，那一块附近的电路就亮** —— 一个以光标为圆心、边缘揉过噪声的软斑 |
| `angleGate(local, sel, w, soft)` + `filmField` | **千年闪** | 半宽 0.100 → **7% ~ 21.7%**（扫满 81 个视角） | 按观察角分组，一条**会随视角滑动的斜波带**扫过卡面（"一批字亮、一批字灭"） |

两个都是**乘在覆盖度（alpha）上**：窗口外那一片 alpha = 0，什么都不画，底下的图层原样留着。
KC 闪那一路还可以换个角度看这件事：**哪儿显形**由鼠标决定，**什么颜色**由观察角决定
（转卡时显形那一块里的走线在变色），两个维度各管一件事。

`angleGate` 那一路有个硬约束：**可见比例最多是 2w**，所以它把 w 一律夹在 `0.125` 以内 ——
这一条夹的是**代码**，不是参数，配方里填多大都突破不了 **45%**。
`local` 由 `filmField(spy)` 给出（"斜向波场 + 一点低频噪声"，取值在 0..1 之间接近均匀分布），
这一点踩过两个坑，都是 `tools/.cache/probe-films.mjs` 扫 81 个视角量出来的：

| 版本 | 做法 | 亮着的比例（81 个视角） |
| --- | --- | --- |
| 第一版 | 拿 fbm 直接当组相位 | **0% ~ 47%** —— fbm 的取值挤在 0.5 附近，窗口一偏就整片全灭 |
| 第二版 | 低频波场（一个卡面约 1 个周期） | 5% ~ 32% —— 相位分布不均匀，选到极值附近就几乎看不见 |
| 现在 | 波场约 3 个周期 + 噪声只有它梯度的 6% | **13.7% ~ 42.2%**，任何角度都 ≤ 45%（KC 闪已改用鼠标窗口，见上表） |

观感上，亮起来的是**一条会随视角滑动的波带**（转卡时像光在卡面上扫过去），
而不是一堆随机斑点 —— 这正是实卡闪膜转起来的样子。

`cursorGate` 那一路的半径是**按实测标的**：理论面积 π·radius² 给出 0.31 就够 45%，
但软边那一圈很淡、掉到肉眼阈值以下就不算"看见"，所以实际得给 **0.33**
（`tools/.cache/probe-kc-cursor.mjs` 量出来：鼠标在卡片正中 43% ~ 45%，
贴到卡片边角时被卡片切掉一部分、掉到 27% 上下 —— 45% 是上限）。

### 爆闪：满卡的等距线栅 → 不规则的拉丝

`parallel`（PR / NPR / RPR / SPR / UPR / Starlight / HL / DLR / CP-TP 共 9 条）原来是
**一条铺满整卡的等距正弦线栅**：

```glsl
float d = (spy.x * ca + spy.y * sa) * uP0.y;        // uP0.y = 92（线密度）
float line = 0.5 + 0.5 * sin(d * TAU);
float sparkle = pow(clamp(line, 0.0, 1.0), uP0.z);  // uP0.z = 2.2（线锐度）
spec *= 0.45 + 0.9 * sparkle;                       // 亮度在 0.45 ~ 1.35 之间摆
```

亮度摆幅 **2.8 倍**、`region = SEL.ALL`（整张卡），所以插画、卡框、效果框全糊着横条。
更要命的是**尺度**：卡片渲染出来只有 400 多像素高，92 个周期 = **6.6px 一根**，
正好落在眼睛看得清的范围内 —— 看到的就是一台 CRT 显示器的扫描线。

这不是"线画粗了"，是**织构选错了**：实卡的膜，线距比屏幕像素细得多，
眼睛分辨不出单根线，看到的是"一片会一起扫过去的光"。所以现在换成
**不规则的拉丝**（各向异性 fbm：跨过线的方向很密、沿着线的方向拉长 13 倍，再按锐度提纯），
方向感保留、**周期没有** —— 既不会有扫描线，也不会随倾斜跟像素栅格打架（摩尔纹）。

判据是**谱**，不是眼睛（`tools/.cache/probe-parallel-lines.mjs`：把卡片区的行均值做 DFT，
看谱上最高那一根是整条谱中位数的几倍 —— 等距横条会在这条剖面上留下一根极高的谱线）：

| 版本 | 谱上最高那一根 | 卡面均值 | 换视角的色相跨度 | 相对平卡 N 的可见度 |
| --- | --- | --- | --- | --- |
| 等距线栅（旧） | **141.7×**（峰位 k=74 ≈ 92 周期 × 卡高的 80%） | 168.8 | 0.913 | 29.6 |
| **不规则拉丝（现在）** | **21.7×** | 170.9 | 0.907 | 27.0 |
| 对照：把织构整个拿掉、只留缓变色带 | 15.7× | 168.0 | 0.928 | 26.1 |

也就是说：线栅那一根**从 141.7 倍掉到 21.7 倍**，而"完全不画织构"的地板是 15.7 倍
（卡面自己内容的谱），已经落回去了；同时膜的浓淡基本没动（卡面均值 / 色相跨度 / 可见度
三列几乎一样）——**动的是织构，不是膜的强弱**。

## 6. 输出约定：覆盖度当 alpha

**每个工艺着色器返回的是 `vec4(完整施加后的颜色, tex.a × 覆盖度)`，而不是 `vec4(颜色, tex.a)`。**

这一条踩过坑，必须写下来：

`name` 只加工卡名笔画，所以很自然地写成 `if (mask < 0.004) return tex;` —— 意思是
"没盖到的地方原样返回"。但返回的 `tex` 带着 `tex.a`（卡内恒为 1），
**等于这一层把整张卡重画了一遍**：它会在上一层的成果上面把原始印刷重新贴回来。

表现是"怎么调都不对"，而且完全不报错：

- 黄金闪的边框怎么调都不变金 —— `metal` 刚把卡框刷成金箔，后面 `name` 一层把它抹回银色
- 浮雕叠三层之后只剩最后一层的作用
- 白碎只有闪粉和白色卡名，棱彩膜整个不见了

改成"**覆盖度当 alpha**"就好了：`mask = 0` 的地方 alpha = 0，那一片**什么都不画**，
底下叠好的东西原样留着。

```glsl
float cover(float mask, float strength) { return clamp(mask * strength, 0.0, 1.0); }
return vec4(col, tex.a * cover(region, uP0.x));
```

纯加光的层（`glitter` / `gloss`）另走**加法混合**（`blendFunc(SRC_ALPHA, ONE)`），
它们只输出"多加了多少光"、不输出卡面颜色，所以也不能按 alpha 去替换底下的画面。

### 卡片外沿是自动识别的

以前这一步是手工量的（拿 `tools/probe-card.mjs` 打亮度剖面找硬边）。多卡之后改成自动，
算法在 **`tools/lib/detect.mjs`** 里 —— 是**唯一一份实现**，被 `embed-card.mjs`
（烘焙时用）与 `verify.mjs`（回归测试用）共用：

```
① 逐行/逐列统计"有多少比例的采样像素同时跳变"（|Δluma| > 26）→ 边缘强度曲线
② 阈值自适应：max(0.5, 0.75 × 这批边缘的最大值)
③ 从上/下/左/右各找第一根过阈值的线当四边
④ 用已知的卡片长宽比 59:86 = 0.686 校正：
   比例明显不对就说明有一对边没找准 → "信边缘更强的那一对，用比例推出另一对"
```

第 ② 与第 ④ 步都是**实测换出来的**：

| 版本 | 做法 | 结果 |
| --- | --- | --- |
| 第一版 | 阈值写死 0.85 | 只在"卡片铺满整幅图"时有效。换一张"卡片只占画面 47% 宽"的图立刻失效（顶边强度只有 0.79）→ 退化成整张图，**卡名掩膜跟着变成 0%** |

| 现在 | 自适应 + 长宽比校正 | 四个合成用例的四边误差：[0,0,1,1] / [0,11,1,0] / [0,0,1,1]，最难的那个老实地退化成整张图 |

`tools/verify.mjs` 的 K 段就是这四个合成用例的回归测试（在页面里现造图、位置自己摆，
所以有确定的标准答案）。**第一版那批测试里我把标准答案写错了** ——
素材是"卡片 + 四周 4% 留白"的纹理，真值却按"整张图 / 粘贴位置"算，
于是每条都差 4%（几十像素），看着像检测不准，其实是标准答案错了。

这张卡自己量出来是 `26,26 → 788,1159`，与手工量的 `26,26 → 787,1157` 差 1~2px。

### 圆角也是量的 —— 而且这张卡量出来是 0

```
沿卡片左沿往里扫，找"卡片边界那根硬边"第几行才回到最左边 → 那个行号就是圆角半径
```

**这张卡的角是方的**（y=26 那一行 x=26 就已经是卡片像素了），量出来 r = 0。

> ⚠️ 这里之前是错的：`CORNER_R = 0.042` 是当初**拍脑袋写的**，注释里还写着"从图上量出来的"。
> 0.042 × 689 ≈ 29px，等于把这四个角各削掉 29px，而且削的是卡片自己的角。
> 现在改成"量到多少就多少，量不出来按 0"，`tools/verify.mjs` 里有一条专门盯这个。

### 换卡要改什么

**卡框 / 卡图窗 / 效果框那几个矩形是按游戏王标准版式写死的比例，所有卡共用。**
这是有意的取舍：同调怪、效果怪、通常怪的版式是一样的，但

- 灵摆卡（多一个灵摆区）
- 连接怪（没有等级星，有连接标记）
- 无效果怪（效果框里只有一句话）

这几种版式对不上，得在 `tools/embed-card.mjs` 顶部的 `CARDS` 表里按文件名覆盖：

```js
const CARDS = {
  'Some Pendulum Card.jpg': {
    regions: { textBox: { x0: 0.04, y0: 0.62, x1: 0.96, y1: 0.80 } },
    nameInk: { lo: 0.30, hi: 0.55, dilate: 2 },   // 深底金字得把阈值反过来
    cornerRadius: 0.028                            // 实测圆角，覆盖自动识别
  }
};
```

**卡名抠图写死了"深字浅底"这个极性**（`NAME_INK`）。真正的金闪原图是金字压深红底，
极性是反的，必须一起改 —— 这一条没有自动检测。

## 11. 多语言（i18n）

界面全量多语言，语言包在 `Languages/`，**每个语言一个 .js**：

```js
global.CardI18nPack['zh-CN'] = { code: 'zh-CN', name: '中文', texts: { 键: 文案 } };
```

| 文件 | 干什么 |
| --- | --- |
| `Languages/languages.js` | 语言清单（有哪些语言、显示名）——加语言改这里 |
| `Languages/zh-CN.js` | 中文（347 键）· 也是缺键时的兜底 |
| `Languages/en-US.js` | English（347 键） |
| `Languages/ja-JP.js` | 日本語（347 键） |
| `js/i18n.js` | 加载 / 切换 / `t()` / `tOr()` / localStorage / `data-i18n` |
| `tools/gen-lang.mjs` | 从 `js/rarities.js` + `js/config.js` 的文案生成 zh-CN 包 |

### 347 个键是怎么分的

| 前缀 | 数量 | 内容 |
| --- | --- | --- |
| `app.` `topbar.` `info.` `panel.` `status.` | 33 | 界面骨架（含「卡图」那一行的 ⟳ 刷新按钮与它的 9 条状态提示） |
| `tier.` / `group.` | 9 | 五个分节 + 参数面板四组（观看 / 工艺 / 区域 / 调试） |
| `rarity.<id>.code` | 3 | 三条没有拉丁文简称的罕贵度（`CP / TP 等` / 韩文版 / 亚洲英文版） |
| `rarity.<id>.short` / `.full` / `.feat` / `.render` | 172 | 43 条罕贵度 × 4 项 |
| `p.<参数名>.label` / `.hint` | 102 | 61 个参数（label 61 个 + 有 hint 的 41 个） |
| `preset.<序号>` | 25 | 25 个预设 |
| `card.<图片名>.name` / `.sub` / `.stats` | 3 | 每张卡在侧栏显示的信息（其余几张卡没有语言包条目，走"缺键回退"用文件名） |

合计 33 + 9 + 3 + 172 + 102 + 25 + 3 = **347**。

### 为什么语言包是 .js 而不是 .json

隔壁 `Three.js-3D-Earth` 用的是 JSON + `fetch`（那份文档的「附：多语言（i18n）说明」）。
**但 `fetch('./Languages/zh-CN.json')` 在 `file://` 下会被 CORS 拦掉** ——
每个本地文件是独立来源。而"双击 index.html 就能跑"是本项目的硬要求，
所以改成 `.js` 语言包 + `<script>` 注入：`file://` 与 http 都能用。

代价是语言包得写成一句 `CardI18nPack['xx'] = {...}` 而不是纯 JSON。

其余机制与那份文档一致：`localStorage` 记住选择、缺键回退到 zh-CN、`{var}` 插值、
下拉框即时切换、加语言只要"丢一个包 + 清单加一行"。

### 三层兜底

```
当前语言的包 → zh-CN 的包 → 代码里的中文原文（js/rarities.js / js/config.js）
```

第三层是刻意留的：`js/ui.js` 里所有文案都用 `I18N.tOr(键, 原文)` 取，
**一个语言包都没加载成功也不会满屏裸键**。`tools/doc-check.mjs` 会核对
zh-CN 包与代码里的原文有没有漂（改了代码忘了改包会被抓出来）。

`tools/doc-check.mjs` 核对的是**本文档里那些能机器判定的说法**，比如：

- 17 个工艺 / 4 个基础件 / 21 个片段着色器 / 43 条罕贵度 / 61 个参数 / 25 个预设
- §3 那张区域表里的数字与 `js/card-textures.js` 里的 `regions` 一致
- 掩膜覆盖率（卡名 2.30% / 卡图 44.2% / 效果框 21.0% / 卡框 29.7%）与生成物一致
- §7 那张表与 `js/rarities.js` 逐行一致
- §8 "做不出来"那几条提到的罕贵度确实存在，而且 `NR` 的图层确实是空的
- 遮罩选择码 0..12 在 `js/shaders.js` 里都有分支

**没能机器核对的**：那些"为什么这么写"的判断（比如"爆闪要沿着垂直线的方向缓慢变色"）是
做出来看着定的，不是验出来的 —— 这类说法在正文里都写了推理依据，你可以自己复核。
