## 0. 一句话

**43 条罕贵度 = 43 份"图层配方"；17 个工艺着色器 = 词汇表；7 块区域掩膜 = 语法。**

罕贵度的差别**几乎全在"哪一块被加工了"**上（面闪只闪卡图、银字只烫卡名笔画、收藏闪是边框+卡名+卡图外环有彩虹），
所以整套系统可以拆成三件互相独立的事：

```
① 区域（语法）  images/*.jpg ──烘焙/现算──▶ 7 块区域的掩膜与矩形
② 工艺（词汇）  17 个片段着色器，每个只会"在给定覆盖度上施加一种工艺"
③ 配方（句子）  43 条 = 一串 (工艺, 参数, 遮罩码) —— js/rarities.js 的一张表
```

渲染时**每一层都采样同一张没加工过的原始印刷**，只输出"我这一层的颜色 + 覆盖度"，
按顺序混进同一个帧缓冲。所以叠几层就是几层、互不污染，加一条罕贵度**不用改渲染代码**。

## 2. 渲染管线

### 2.1 WebGL2 上下文

```js
canvas.getContext('webgl2', {
  alpha: false, antialias: false, depth: false, stencil: false,
  premultipliedAlpha: false,     // 直通 alpha，配合自己的覆盖度合成
  preserveDrawingBuffer: true,   // 无头 readPixels 取像要用
  powerPreference: 'high-performance'
});
```

- **没有 FBO、没有 ping-pong**：全程直接画进默认帧缓冲（`js/` 里搜不到 `createFramebuffer`）。
- 三张纹理：`uTex`（卡图）/ `uMask`（掩膜）/ `uStamp`（图案图集），
  `CLAMP_TO_EDGE` + `LINEAR` + mipmap（`LINEAR_MIPMAP_LINEAR`），上传时**不翻转 Y**（纹理第 0 行 = 图片第 0 行）。
- 画布尺寸 = `#stage` 的 CSS 尺寸 × `min(devicePixelRatio, 2)`；
  `#stage` 上挂 **`ResizeObserver`** —— 参数面板开合只改 CSS grid，不会触发 window `resize`（这是踩过的坑，见 §8.4）。

### 2.2 每帧的 draw step

```
drawFrame()
 ├─ 关混合 · clearColor(0,0,0,1) · clear
 ├─ ① bg         全屏四边形（屏幕坐标）        渐变 + 缓慢横移光带 + 暗角
 ├─ 开混合（标准 alpha）
 ├─ ② shadow     卡片四边形（偏移 0.8%·放大 1.012·α0.42） black + 25 抽样软边
 ├─ ③ base       原始印刷          ← 或 maskDebug 打开时画 maskdebug
 ├─ ④..⑥ 工艺层  按 js/rarities.js 的配方顺序，一层一个 drawArrays
 ├─ ⑦ demoLayer  「区域演示」调试层（只盖星带 / 属性圆）
 ├─ drawOverlay() 2D canvas：一览模式的名字标签 / 图案图集预览
 └─ 关混合 · gl.finish()
```

- **一次 draw step = 一次 `gl.drawArrays(TRIANGLES, 0, 6)`**：6 个顶点的卡片四边形（或全屏四边形）。
- 每帧的 draw call 数 = `bg? + shadow? + 1 + 图层数 + demo?`
  → 面闪 SR 3 层 = **6** 次；最多的一条（UR / UTR / 20th SER / GScR / PlScR / KC / DT-UR / 亚英 4 层）= **7** 次。
- **一览模式**：43 格 × (1 + 各自图层数) + 1 ≈ **148** 次（`passCount()` 给的估计值不含每格自己的投影）。
- 开销其实很小（每帧几百个三角形），真正贵的是**每层都要重绑一遍三张纹理**、
  并且每次 `bufferData(..., STREAM_DRAW)` 重传顶点；帧尾那句 `gl.finish()` 是唯一强制同步点。

### 2.3 合成约定：**覆盖度当 alpha**

这是整个项目最容易被写错、也最值得记住的一条约定：

```glsl
float cover(float mask, float strength) { return clamp(mask * strength, 0.0, 1.0); }
// 每个工艺着色器返回：
return vec4( /* 满强度施加后的颜色 */ , tex.a * cover(region, uP0.x) );
```

- 混合：普通层 `blendFuncSeparate(SRC_ALPHA, ONE_MINUS_SRC_ALPHA, ONE, ONE_MINUS_SRC_ALPHA)`。
- 加光层（`glitter` / `gloss`，`SH.ADDITIVE`）走 `blendFuncSeparate(SRC_ALPHA, ONE, ONE, ONE)`，
  **只输出"多加了多少光"**，所以它们不输出卡面颜色、也不能按 alpha 替换底下的画面。
- 半覆盖的层要提前返回时，**必须返回 `vec4(tex.rgb, 0.0)`，不能返回 `tex`**
  —— `tex` 的 alpha 在卡内恒为 1，等于这一层把整张卡用原始印刷重画了一遍（§8.4 第 1 条）。

### 2.4 3D 倾斜顶点着色器

```
p = vec3(aPos - uCenter, 0)          // 卡片局部坐标（像素，y 向下）
p = rotY(p, uTilt.y)                 // 先绕 Y
p = rotX(p, uTilt.x)                 // 再绕 X
z = max(p.z + uDist, uFocal * 0.25)
k = uFocal / z
screen = uCenter + p.xy * k
ndc    = (screen.x/uResolution.x*2-1, 1 - screen.y/uResolution.y*2)
gl_Position = vec4(ndc * w, 0.0, w)  // ← w = z/uDist，不是 1
```

- **`w = z/uDist` 是关键**：让纹理坐标按透视插值，倾斜时卡面不会错位。
- `uDist = uFocal = 画布高 × 1.75`（`CAM_DIST`）；最大倾斜 `TILT_MAX = 0.62 rad ≈ 35°`。
- **同一对倾斜角同时驱动闪膜的衍射相位**：JS 侧
  `uView = clamp(smoothTilt.yx / TILT_MAX × 视角灵敏度, ±1.6)`（注意 x/y 是**交叉**的），
  着色器里再进 `spectrum(ph, grain)` 的相位与 `angleSel()`。观感上这就是"捏着卡慢慢转"。
- 鼠标在卡内时 `uMouse = 光标`（KC 闪的可见窗口用它），离开卡面时退回 `viewPoint()`。
- `smoothTilt` 是指数平滑（`k = min(1, dt/0.14)`）；**定格渲染 `renderAtTime(t)` 直接跳到目标角**，保证可复现。

### 2.5 时间、确定性与取像

| 接口 | 说明 |
| --- | --- |
| `render(ts)` | rAF 驱动，`dt = min((ts-last)/1000 × 时间倍率, 1/15)`，累加到 `this.time` → `uTime` |
| `setPlaying(false)` | 停 rAF；此时改参数仍会立刻重绘一次（面板交互要用） |
| `reset()` | `time = 0`（↻ 按钮） |
| `renderAtTime(t)` | **定格渲染**：停 rAF、`time = t`、`smoothTilt` 直接设为 `targetTilt()`、画一帧 —— 无头验证与截图全走它 |
| `pixels()` / `cardRegionPixels()` / `diffPixels()` / `cardRegionStats()` | readPixels → 逐像素差 / 均值 / 饱和 / 亮部比例 |
| `passCount()` / `activeShaders()` | 诊断：这一帧几个 draw step、用到哪些着色器 |

**一览模式**给每格一个不同的 `uSeed = (i × 7.13) % 100`，否则 43 格的闪膜图案会一模一样；
另外一览模式**不做 3D 倾斜**（格子小，倾斜只会互相打架）。
注意一览模式**不会切卡图** —— 43 格采样的是当前选中的那张卡。

### 2.6 关于「渲染分辨率」这个滑条（复核发现，见 §9.2）

`scale` 的实现是 `viewW/viewH = 画布像素 × scale`，而 `gl.viewport` 始终是整块画布、
投影又把 `viewW` 个单位映射到整屏 —— 所以它**改不了光栅分辨率**（没有 FBO，像素数一个不少），
画面构图也几乎不变。实测（`tools/.cache/probe-scale.mjs`）：

```
scale=1    画布 880×880  view 880×880   卡片四边形 471×686   逐像素差 (基准)
scale=0.7  画布 880×880  view 616×616   卡片四边形 330×480   逐像素差 mean 0.01 / max 7
scale=0.4  画布 880×880  view 352×352   卡片四边形 188×275   逐像素差 mean 0.02 / max 13
```

也就是说：**画布像素数没变、构图没变，只有"以 view 为单位的像素量"**（投影模糊半径、浮雕梯度步长、闪粉尺寸、圆角抗锯齿）
跟着变。面板上写的"内部渲染倍率，掉帧就调低"与实际行为不符 —— 详见 §9.2 的完整说明与修法。

### 3.3 两套"可见窗口"：图案膜永远只显形一部分

实卡的图案膜（KC 的线路、千年的象形字）**不是整片一起反光**的：微结构分成许多组，每组只在某个条件满足时把光反进眼睛。
所以 `kc` 与 `millennium` 虽然铺满整卡，但**只显形一部分**，而且这一部分是乘在覆盖度（alpha）上的 —— 窗口外 alpha = 0，底下的图层原样留着。

| 窗口 | 用在哪 | 机制 | 实测可见面积 |
| --- | --- | --- | --- |
| `cursorGate(spy, radius)` | KC 闪 | **以光标为圆心的软斑**，边缘揉噪声、对焦最亮往外渐变 | 半径 0.31 → `π·0.31²/0.6729 ≈ 45%`；实测卡片正中 43~45%，贴边角 27% 上下 |
| `angleGate(local, sel, w, soft)` + `filmField` | 千年闪 / 法老闪 | 观察角给"选择相位"，`filmField` 给"组相位"，环上距离 < 半宽才显形 → 一条**随视角滑动的斜波带** | `w = 0.100` 时扫满 81 个视角：**7.0% ~ 21.7%** |

- **45% 是代码里的硬天花板**：`float hw = min(w, 0.225);`（环上可见长度 = 2w），配方里填多大都突破不了。
- `filmField` 的两个坑都是实测换出来的：**fbm 不能直接当组相位**（取值挤在 0.5 附近 → 亮着的比例在 0%~47% 之间跳），
  **波场频率不能太低**（一个卡面才一两个周期时相位分布不均 → 选到极值附近几乎全灭）。
  现在 = 波场约 3 个周期 + 噪声只有它梯度的 6%。
- KC 闪则是"**哪儿显形**由鼠标定、**什么颜色**由观察角定"，两个维度各管一件事。

### 3.4 三个值得单独讲的实现

**① KC 闪的电路板（四层铜）** —— `boardCopper` 叠四层，每层的走向场、留白阈值、疏密、线宽都不同：
走线成组地朝一个方向走很长一段（45° 折角），线的尽头压**过孔**（`hw*1.6` 的焊盘），
少数几根是 1.8 倍宽的"电源线"，板上留着一片片没铜的空地 —— 是一块**板子**而不是迷宫网格。
配色 `boardPalette` 是**分段线性插值**的连续渐变：色相锚点 0.593（蓝）→ 0.330（绿）→ 0.195（黄）→ 0.077（橙）→ 0.013（红），
按**到光标的距离**铺开，所以"对焦那圈最亮、往外一路渐变"。

**② 爆闪：从等距线栅换成各向异性拉丝** —— 原来的 `parallel` 是一条铺满整卡的等距正弦线栅（密度 92），
卡片只有 400 多像素高，算下来 **6.6px 一根** —— NPR/RPR/SPR/UPR/PR 看着都像 CRT 扫描线。
现在换成 `across = dot(spy, dir) × 密度`、`along = dot(spy, ⟂dir) × 密度 × 0.075`（13.3:1 拉长）的各向异性 fbm：
方向感保留、**周期没有**。判据不是眼睛而是**谱**（卡片区行均值做 DFT）：

| 版本 | 谱上最高那一根 | 卡面均值 | 色相跨度 | 相对平卡 N 的可见度 |
| --- | --- | --- | --- | --- |
| 等距线栅（旧） | **141.7×** | 168.8 | 0.913 | 29.6 |
| 不规则拉丝（现在） | **21.7×** | 170.9 | 0.907 | 27.0 |
| 对照：完全不画织构（地板） | 15.7× | 168.0 | 0.928 | 26.1 |

**③ 浮雕 / 金属 / 幽灵** —— `emboss` 把卡面明暗当高度场，中心差分求法线再用方向光打亮
（`uResolution` 决定梯度步长，`embossDetail` 是放大倍数）；`metal` 是**明暗映射**到金属色（不是加增益，否则整卡炸白糊掉）；
`ghost` 是"去色 + 提对比 + 冷偏移 → 银白幽灵"，并在观察角波峰那一段整片换成面闪的膜，所以捏着转能看到它"变回面闪"再变回来。

## 4. 区域与遮罩系统

### 4.1 遮罩选择码（这份清单就是整个项目的核心词汇表）

| 码 | 含义 | 码 | 含义 |
| --- | --- | --- | --- |
| 0 | 全卡面 | 7 | 卡框 + 卡图外环 |
| 1 | 卡图（插画本身） | 8 | 效果框里的字（按暗度从效果框里抠） |
| 2 | 卡框（整卡 − 卡图窗外框 − 效果框） | 9 | 卡框 + 卡名 |
| 3 | 卡名笔画（掩膜 R 通道） | 10 | 卡图 + 卡名 |
| 4 | 效果框（含 ATK/DEF 带） | 11 | **星数 / 阶数带**（整宽一条） |
| 5 | 卡图 + 卡框 | 12 | **属性圆** |
| 6 | 金属区 | 13 | **星带 + 属性圆**（两块一起） |

> ⚠️ **复核发现**：代码里 **6 与 7 是同一个分支**（都是 `max(frame, ring)`），
> 但 `shaders.js` 的注释与两份文档都写"6 = 金属区（卡框 + 卡名 + 卡图外环）"。
> 实际效果不受影响（`metal` 那几条配方后面都跟着一层 `name`，卡名照样烫金），但**语义与文档不符**。详见 §9.3。

### 4.2 哪些区域是烘焙的、哪些是现算的

| 区域 | 来源 | 为什么 |
| --- | --- | --- |
| 卡名**笔画** | **必须烘焙**（掩膜 R 通道） | 笔画是从图里按暗度抠的，矩形算不出来 |
| 卡片剪影 | **必须烘焙**（掩膜 A 通道） | 圆角 / 留白 / 边缘只用运行时 uniform 控制 |
| 卡图窗外框 / 卡图内容 / 效果框 | **运行时按矩形现算** | 本来就是纯几何；挪进着色器之后侧栏拖滑条**实时生效**，不用重烤 35 秒 |
| 星数 / 阶数带 · 属性圆 | **运行时现算**（矩形 / 圆） | 后加的两块，本来就没有烘焙值；实测 7 张卡之间差异只在第 4 位小数 |
| 卡框 / 卡图外环 | 由上面几块**推出** | `frame = card × (1 − outer) × (1 − text)`、`ring = outer × (1 − inner)` |

侧栏「区域」组 20 根滑条里，`regionManual`（默认开）决定前三个矩形用**滑条值**还是用**烘焙值**；
星带与属性圆**两种模式下都用手调值**（它们不吃这个开关）。

### 4.3 掩膜通道分配，以及那个预乘 alpha 的坑

```
R = 卡名笔画（Otsu 阈值 + 膨胀 2px）
G = 卡图内容（artInner 矩形 → 3×3 盒糊两遍 ≈ 1.5px 羽化）
B = 效果框（textBox 矩形 → 同上）
A = 卡片剪影（卡内恒为 1）
```

**"卡框"与"卡图外环"刻意不进掩膜**，由着色器按矩形现算。
原因是第一版把 A 通道定义成"卡框"：卡图窗与效果框那两块上 A = 0，
而 canvas 的像素是**预乘 alpha** 存的，`toDataURL` / `getImageData` 会反预乘 —— 除以 0，G/B 通道被抹平。
更阴的是**画面看着完全正常**（GPU 上传走的是 `<img>` 里的原始像素、不经过 canvas），
只有"把掩膜过一遍 canvas"的代码才看得见。现在 alpha 让给"是不是卡上的像素"（卡内恒 1，怎么反预乘都不丢），
`verify.mjs` B 段有一条专门盯这个往返。

### 4.4 区域默认值（运行时，卡片相对坐标）

| 区域 | 默认值 | 备注 |
| --- | --- | --- |
| 卡图窗外框 `artOuter` | 0.1009 / 0.1673 / 0.9003 / 0.7180 | 手调值（原来的烘焙映射值差半个像素） |
| 卡图内容 `artInner` | 0.1180 / 0.1813 / 0.8855 / 0.7033 | |
| 效果框 `textBox` | 0.0510 / **0.7420** / 0.9480 / **0.9467** | 上下沿是手调的（含 ATK/DEF 带） |
| 星数 / 阶数带 `uRectStar` | 0.0320 / 0.1200 / 0.9350 / 0.1800 | 整宽一条：等级星靠右、阶数星靠左都能盖住 |
| 属性圆 `uCircleAttr` | 圆心 (0.8831, 0.0759) · 半径 **0.0320**（单位"卡高 = 1"）· 软边 0.0015 | 走圆掩膜而不是方块，才不会连带加工卡框 |

## 5. 配方层 `js/rarities.js`

### 5.1 条目结构与 `like:` 继承

```js
{ id, code, cn, en, tier, feat, render, layers, like?, like_note? }
// feat  = 原始文档里那一句"主要特征"（说明条上原文照抄）
// render= "怎么做的"（支持 **加粗** 与 `代码`，ui.js 的 rich() 渲染）
// layers= [ { shader, p0, p1, p2, col } ]  ← 缺的 p* 默认 [0,0,0,0]，col 默认白
```

继承只用一行：`r.layers == null` 时深拷贝 `BY_ID[r.like].layers`（`p0/p1/p2/col` 各自 `.slice()`），
没有 `like` 又没有 `layers` 直接 `throw`。**这里必须写 `== null` 而不是 `=== null`**：
DT 那 6 条压根没写 `layers` 这个键（是 `undefined`），用 `=== null` 会让兜底分支
把它们统统变成"一个图层都没有"的平卡 —— 这个 bug 曾经真的存在过（9 条 `like`：`NR` 只借标签、其余 8 条借图层）。

## 6. 参数 / 界面 / 多语言 / hash

### 6.1 61 个参数（4 组）

| 组 | 个数 | 成员 |
| --- | --- | --- |
| 观看 | 16 | `card rarity intensity viewGain tiltAmount hoverOn tiltInvert autoSway swaySpeed speed cornerPx cardSize scale shadowOn bgOn bgSpin` |
| 工艺 | 20 | 12 个工艺倍率（`mName mHolo mParallel mDiagonal mPrismatic mEmboss mMetal mRainbow mGhost mGlitter mPattern mStamp`）+ 颜色覆盖 4 个 + `embossAngle embossDetail stampAmount glitterSize` |
| 区域 | 20 | `regionManual` + 三个矩形 × 4 + 星带 × 4 + 属性圆 × 3 |
| 调试 | 5 | `maskDebug demoRegion sheetOn layerOnly stampCells` |

- 参数在 `js/config.js` 的 `SPEC` 里声明一次，**面板是数据驱动生成的**（`ui.js` 里没有一行参数 HTML）。
  类型支持：`range` / `check` / `select` / `color` / `card`。
- **强度三级缩放**：`实际强度 = 配方里的强度 × 工艺总强度(intensity) × 该工艺的倍率(mHolo/mMetal/…)`。
  面板不给每个 uniform 做滑条（那会是几百根），而是**每个工艺一个倍率** —— 目的是让人一边拖一边看清这个工艺在干什么。
- 双向绑定：控件 → `p.setParam()` → `onParamsChanged` → `syncPanel()` + `syncInfo()` + `writeHash()`。
  唯一的"状态机"就是这个 `params` 对象；`playing` 是另一个独立标志。

### 6.2 hash 编解码

- **位置式**：按 `SPEC` 顺序、逗号分隔，61 个参数 → 约 **237 字符**；没有版本号也没有键名。
  `range` 按 `step` 决定小数位（`0.0001 → 4 位`、`0.05 → 2 位`），`color` 是 6 位十六进制，`check` 是 `1/0`。
- `decode` 从默认值出发，缺项/空项**跳过**（保留默认）；所有值都过 `clampParam`，非法输入被夹紧或丢弃、永不抛错。
- ⚠️ `clampParam` 对开关必须写 `Number(v) ? 1 : 0` —— hash 解出来是字符串，`'0'` 在 JS 里是**真值**（踩过）。
- ⚠️ 没有版本号 ⇒ **参数顺序一变，老链接会被静默解释成别的参数**。详见 §9.6。

### 6.3 多语言：语言包是 `.js` 不是 `.json`

```js
global.CardI18nPack['zh-CN'] = { code: 'zh-CN', name: '中文', texts: { 键: 文案 } };
```

- **为什么不用 JSON**：`fetch('./Languages/zh-CN.json')` 在 `file://` 下会被 CORS 拦掉，
  而"双击 `index.html` 就能跑"是本项目的硬要求。改成 `<script src>` 注入，`file://` 与 http 都能用。
- **三层兜底**：当前语言包 → zh-CN 包 → 代码里的中文原文。`ui.js` 里所有文案都走 `I18N.tOr(键, 原文)`，
  所以**一个语言包都没加载成功也不会满屏裸键**。
- 347 键 = 界面骨架 33 + 分节/分组 9 + 43 条 × 4 项 + 3 条 code + 61 参数（61 label + 41 hint）+ 25 预设 + 每张卡 3 项。
- **没有目录扫描**：`Languages/languages.js` 是一份手写清单（3 条），加语言 = 丢一个包 + 清单加一行 + 刷新页面（`⟳` 就是 `location.reload()`）。

## 7. 烘焙与识别流水线

### 7.1 外沿识别 `js/detect.js`（`detectCardRect(sp, W, H)`）

```
① 逐行/逐列统计"同时跳变的采样像素比例"（|Δluma| > 26，只取中段 60% 躲开暗角）→ 边缘强度曲线
② 阈值自适应：max(0.5, 0.75 × 该方向强度最大值)
③ 四个方向各找第一根过阈值的线当四边
④ 比例校正（|宽高比 − 0.686| > 0.03 时才动手）：
   先试"对称镜像"四种组合（弱边关于图像中线镜像），取面积最大且比例合格的候选；
   再退化到"信更强的那一对边，用 59:86 推出另一对"
⑤ 合法区间检查：比例 0.60~0.78、面积 ≥ 12%，否则老实退回整张图
```

- **`tools/lib/detect.mjs` 里只有一行**：把 `js/detect.js` 的**源码文本**读出来，
  tools 侧 `eval` 之后直接调用 —— 页面与工具跑的是**同一份字节**，不会出现两套实现漂移。
- 三个版本都是实测换出来的：写死阈值 0.85（只对"卡片铺满整图"有效）→ 自适应阈值
  （浅卡贴浅底时上边找不到，比例算成 0.7425）→ 自适应 + 59:86 校正。
- **本轮 10 张卡实测**：10/10 自动识别成功，其中 **5 张**走 `both-axes`（两对边都够强直接信），
  **5 张**走 `mirror-both`（深色卡框那张，下沿或右沿强度是 0.00 —— 边缘根本不存在，只能靠比例补）。
  识别出的比例全部落在 0.6717 / 0.6726（真卡 59:86 = 0.6860；实拍照片因为投影与描边普遍偏小）。

### 7.2 烘焙 `js/bake.js`（`bakeCard(src, opts)`）

```
0. 整张原图 getImageData → detectCardRect 得到 cardRect
1. 卡面纹理 = **整张原图**（不裁、不缩、不留白），region 常量线性映射到整图坐标
2. canvas 圆角（现在固定 0，圆角改成运行时的 uCardRound）
3. 掩膜逐像素：G = artInner 矩形、B = textBox 矩形、A = 卡内恒 1
   R = 卡名笔画：卡名带直方图 → **Otsu** 阈值 → 少数派即笔画（自动判极性）
     → 软阈值（ramp 0.045）→ 3×3 最大值膨胀 2 遍（≈2px）
4. G/B/A 各做两遍 3×3 盒糊（≈1.5px 羽化）；R 不羽化
5. 统计覆盖率：卡名 / 卡图 / 效果框 / 卡框 / 外环 / 不透明比例
6. 输出记录（toEntry）：id file sha256 sourceWidth/Height cardRect cardDetected
   cornerRadius(+Source) width height aspect margin contentUV contentWidth/Height
   contentAspect regions nameInk nameInkStats maskCoverage dataUri maskUri
```

- 编码：卡图 **webp q0.95**（每张 300~420 KB）、掩膜 **png**（37~41 KB），都以 data URI 内嵌。
  **为什么内嵌**：Chrome 把每个本地文件当独立来源，`file://` 下用本地 `<img>` 做 `texImage2D` 会因"来源不干净"被拒。
- ⚠️ **存进 `card-textures.js` 的 `regions` 是"整图相对"**（除以整图 W/H），
  而 `js/bake.js` 顶部的 `REGIONS` 常量是"卡片相对" —— 两套口径都合法（`MARGIN = 0` 时数值恰好不同），
  但正是这个口径差让 `doc-check.mjs` 的 5 条区域核对一直过不了（§9.5）。
- **卡名极性现在是自动的**（Otsu + 少数派），本轮 10 张里 9 张判成"深字浅底"、`Raidraptor` 判成"白字黑底"（两边亮度差 0.741）。
  ⚠️ 但 `总结.md` / `README.md` / `rarity-shaders.md` 里仍然写着"卡名抠图写死了深字浅底的极性，没有自动检测" —— **这条已经过期**（§9.4）。

### 7.3 浏览器内 ⟳（`js/card-refresh.js`）

| 环境 | 怎么发现新图 | 注意 |
| --- | --- | --- |
| `http://` | `fetch('images/?t=时间戳', {cache:'no-store'})` 读目录索引，`DOMParser` 解析 `a[href]` | 先判 `content-type` 含 html，避免拿到 SPA 的 index.html 当目录 |
| `file://` | 浏览器**不给读目录**，而且本地图会让 canvas 变脏（`getImageData` 抛 `SecurityError`）→ 弹文件选择框，`FileReader.readAsDataURL` 读成 data URI 再烤 | "取消"不会触发 `change`，用一次性 `focus` 监听 + 1200ms 兜底；`Shift` + 点击强制手动选 |

烤好的卡 `runtime: true`、`sha256: null`，只进内存（`CardTextures.list/byId/order`），**刷新页面就没了**；
要长期留下必须跑 `node tools/embed-card.mjs`。它调的就是 `js/bake.js` —— 与工具**同一份实现**。

### 8.4 工具真的抓出来的东西（挑代表性的）

1. **部分覆盖的层会把整张卡重画一遍** —— `if (mask < 0.004) return tex;` 看着无害，
   返回的 `tex` 带 `alpha = 1`，等于在上一层成果上把原始印刷贴回来。表现是"黄金闪怎么调都不变金"，而且**完全不报错**。
2. **canvas 的预乘 alpha 会吃掉掩膜** —— 画面还看着完全正常（GPU 上传不经过 canvas），只有把掩膜过一遍 canvas 才看得见。
3. **`like:` 只认 `null`、不认"没写这个键"** —— DT 那 6 条压根没有 `layers` 键，
   于是统统退化成"一个图层都没有"，**DT-R/DT-SR/DT-UR/DT-SER/DT-PR 渲染出来和平卡逐像素相同**（差 0.000）。
4. **打开参数面板卡片会变小** —— 画布只监听 window `resize`，而面板开合改的是 CSS grid，没有 window 事件。
   现在用 `ResizeObserver` 盯 `#stage`。
5. **倾斜的两个轴方向相反** —— 鼠标往右是"右边朝你翘"、往下却是"下边往里沉"；单看一个方向都说得通，斜着晃鼠标才发现两边在打架。
6. **"关掉鼠标驱动倾斜"后定格画面照样跟鼠标跑** —— 实时与定格各抄了一份倾斜计算，定格那份漏了开关（单通道差 252）。
7. **hash 里的 `'0'` 被读成"开"** —— 字符串 `'0'` 在 JS 里是真值，`clampParam` 改成 `Number(v) ? 1 : 0`。
8. **卡面扫光有 40% 时间是死的** —— `gloss` 用 `max(sin, 0)`，实测 t = 2~5s 整整四秒卡片区平均差正好是 0 → 改成 `abs(sin)` + 常驻底光。
9. **圆角半径是拍脑袋写的** —— `CORNER_R = 0.042` 注释里写着"从图上量出来的"，其实没量过；把像素摊开一看这张卡的角是**方**的。
10. **卡片外沿检测的阈值写死 0.85** —— 只对"卡片铺满整幅图"有效；造一张"卡片占画面 47% 宽"的测试图立刻失效。
11. **投影被调成了黑边** —— 为了让参数扫描判它"接通"，加到 0.70 不透明，量出来卡片下沿外侧亮度只有 9（远处背景 29）。
12. **检测器的测试里，标准答案自己写错了** —— 素材是"卡片 + 四周 4% 留白"，真值却按"整张图"算，每条都差 4%，看着像检测不准。
13. **爆闪的等距线栅看起来像 CRT 扫描线** —— 判据从眼睛换成**谱**之后才收干净（§3.4）。

## 9. 本轮复核发现的问题（诚实清单）

下面这些**都不是渲染缺陷**，而是"文档 / 注释 / 自检与代码不一致"和少量死代码。
按"值得修"排序，每条都给了复现方式。

### 9.1 `verify.mjs` 的"卡数一致"是一条同义反复（**最值得修**）

```js
const n = T.list.length;                     // tools/verify.mjs:724
const list = T.list.map(...);                // :739
check('生成物里的卡数与 images/ 下的图片数一致', cards.n === cards.list.length, ...)  // :750
```

`cards.n` 与 `cards.list.length` **都来自 `window.CardTextures.list`**，所以这条永远成立。
本轮实测就撞上了它：烤之前 `images/` 里已经有 **10 张图**、`js/card-textures.js` 里只有 **7 张**，
63 项照样全 PASS。这条检查想防的正是"新丢了图但忘了跑 embed-card"，现在防不住。
**修法**：在 Node 侧 `readdirSync(images/)` 数一遍图片，与 `CardTextures.list.length` 比。

### 9.2 `scale`（「渲染分辨率」）标签与实现不符，而且会让**取像区域**错位

- 实现见 §2.6：没有 FBO ⇒ 画布像素数不变，**降不了分辨率**；逐像素实测 scale = 1 vs 0.4 只有 mean 0.02 / max 13 的差别。
- 顺带一个真问题：`cardContentRect()`（`js/pipeline.js:884`）用**卡片四边形（view 单位）**去算取像框，
  却拿 `canvas.width/height`（画布像素）当边界并直接喂给 `readPixels` —— 两者只在 `scale === 1` 时相等。
  于是 `cardRegionPixels()` / `cardRegionStats()` 在 `scale ≠ 1` 时量的是画面**左上角**一块错误区域。
  `effects.mjs` 的逐参数扫描正好会给 `scale` 试 0.4 这个候选值，量出来"均值差 138.14 / 90.72% 像素变化"——
  **那条"生效"是量错了，不是画变了**。
- **修法**：要么给 `scale` 接一个真的低分辨率 pass（FBO + blit），要么把标签改成它实际做的事（"逻辑单位缩放 / 像素量级"），
  并把 `cardContentRect()` 里的 view 单位乘回 `1/scale`（或在 `scale ≠ 1` 时拒绝量测）。

### 9.3 `pickMask` 的 6 与 7 是同一个分支，与注释/文档不符

```glsl
if (s < 6.5) return max(frame, ring);   // 6「金属区」—— 注释说是"卡框 + 卡名 + 卡图外环"
if (s < 7.5) return max(frame, ring);   // 7「卡框 + 卡图外环」—— 与 6 逐字相同
```

`js/shaders.js:207` 的注释、`rarity-shaders.md` §4 的码表、`总结.md` 都写着 6 含卡名。
实际 `metal` 那几条配方后面都跟着 `name` 层，所以**观感没问题**，但语义是错的。
**修法**：要么把 6 改成 `max(frame, ring, m.r)` 让代码追上文档，要么把文档改成"6 与 7 等价（保留两档是为了语义清晰）"。

### 9.4 "卡名极性写死深字浅底"这条说明已经过期（**本次已改正**）

`js/bake.js` 现在默认 `NAME_INK.auto = true`：Otsu 阈值 + **少数派即笔画** ⇒ 极性自动判定，
本轮 10 张里 `Raidraptor` 就自动判成了"白字黑底"（`verify.mjs` C 段还有一条专门断言"每张卡的卡名极性都是自动判出来的"）。
但 `README.md`（已知取舍）、`总结.md` §4、`rarity-shaders.md` §10 都仍写着"写死了深字浅底、没有自动检测，真金闪必须一起改"——
按它会白改一遍阈值。**这三处本次已经改成"自动判极性；`nameInk: {auto:false, lo, hi}` 可钉死"**。

### 9.5 `doc-check.mjs` 的 8 项失败：全是文档落后于代码

| 失败项 | 文档写的 | 生成物实际是 |
| --- | --- | --- |
| §3 区域表 · 卡名带 / 卡图窗外框 / 卡图内容 / 效果框 / 等级星带（5 条） | **卡片相对**比例 | `card-textures.js` 存的是**整图相对**（`MARGIN = 0`，两套口径数值不同） |
